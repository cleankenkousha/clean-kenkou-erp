# Clean KENKOU ERP 設計ガードスキル (kenkou-erp-design-guard)

このスキルは、「Clean KENKOU ERP」の開発において、設計書・業務ルール・データベース・UIUXの整合性を常に維持するために適用する。

---

## 1. 最重要原則（プロジェクト憲章より）

### ① 牛若丸との役割分離

* **牛若丸が担当する領域** : 定期ルート回収、定期顧客管理、日常の収集業務、ルート運行管理、定期回収実績
* **Clean KENKOU ERPが担当する領域** : 電話受付、顧客管理、案件管理、見積管理、スポット回収管理、請求管理、売上分析、経営ダッシュボード、AI支援（OCR/音声入力/アシスタント）
* **禁止事項** : 牛若丸の定期ルート配車機能を当システムに再実装しない。

### ② 設計ファースト & 仕様変更順序

* コードを書く前に、必ず該当する `docs/` 配下の設計書を確認する。
* 仕様変更が発生した際は、必ず **「設計書（Markdown） → コード」** の順に修正する。

### ③ UI/UX設計思想

* **テーマ** : 「考えなくても操作できる業務システム」
* **目標** :
  * 電話受付30秒以内に入力完了できる動線
  * 3クリック以内で主要操作が完了すること
  * 視線移動最小 / 入力最小 / キーボード中心操作

### ④ システム変更時のバージョン更新義務（最重要運用ルール）

* **必須要件**: システムの変更（機能追加・バグ修正・仕様改善・UI調整）を行った場合は、**例外なく必ずバージョン番号をインクリメント**する。
* **更新対象ファイル**:
  1. `src/version.ts`: `APP_VERSION`（例: v1.1.2 → v1.1.3）、`APP_BUILD_DATE`（現在日時）、`APP_DESCRIPTION`（変更内容の要約）を更新。
  2. `package.json`: `"version"`（例: "1.1.3"）を同期更新。
* **目的**: 現場端末（PC・タブレット・スマートフォン）のブラウザキャッシュによる新旧バージョンの齟齬を即座に視覚確認・防止するため。

## 2. 実装前・実装後の自動チェックリスト

機能追加・修正・リファクタリングを行う際は、以下のステップを順次確認する。

### Step 1: 関連設計書の特定と確認

| 変更内容 | 参照・更新すべき設計書 |
| :--- | :--- |
| 画面レイアウト・カラー・コンポーネント | `docs/01_UIUX_Design_Book.md` |
| 画面遷移・認証・ロール・アーキテクチャ | `docs/02_System_Design_Book.md` |
| 見積計算・税率・ステータス遷移・業務ロジック | `docs/03_Business_Rules_Book.md` |
| テーブル追加・カラム変更・RLSポリシー | `docs/04_Database_Design.md` |
| API連携・外部連携（Supabase Edge Functions等） | `docs/05_API_Design.md` |
| AI機能（OCR・音声・アシスタント等） | `docs/06_AI_Design_Guide.md` |
| 開発環境・コーディング規約・Git運用 | `docs/07_Development_Guide.md` |
| テスト項目・受入基準 | `docs/08_Test_Design.md` |

### Step 2: データベースとRLSの整合性ルール

* 新規テーブルやカラム追加時は、必ず `supabase/` 配下にマイグレーションSQLを作成する。
* すべてのテーブルで **Row Level Security (RLS)** が有効化されていることを確認する。
* `src/types/database.types.ts` 等のTypeScript型定義を最新スキーマと同期する。

### Step 3: 印刷・帳票・インボイスの整合性ルール

* 見積書・請求書を出力する際は、以下を漏れなく保持すること：
  * 適格請求書（インボイス）登録番号（`T` + 13桁）
  * 税率区分（10%標準税率、対象額、消費税額）
  * 自社情報（有限会社山鹿健康社、住所、TEL/FAX、振込先口座）
  * 顧客名・発行日・品目明細

### Step 4: バージョンインクリメントとビルド・デプロイ検証

* コード変更完了後、必ず `src/version.ts` と `package.json` のバージョン番号・ビルド日時を更新する。
* `npm run build` を実行し、TypeScriptの型エラーおよびビルドエラーがないことを確認する。
* Supabase Edge Functions を変更した場合は即座に再デプロイし、フロントエンドは Git コミット＆プッシュ（Netlify自動デプロイ連携）を行う。

## 3. ガードアクション（AI動作指針）

ユーザーから機能開発や仕様変更の依頼を受けた際、AIは以下のように振る舞う：

1. **要件確認時**: 該当する設計書を参照し、既存の設計書や業務ルールと矛盾がないか確認する。
2. **変更実施時**: コード変更とセットで、該当する `docs/*.md` のドキュメント更新を提案・実施する。
3. **バージョン更新時**: システム変更時は必ず `src/version.ts` と `package.json` を更新し、`npm run build` で検証する。
4. **完了報告時**: 設計書、コード、バージョン番号（`vX.Y.Z`）、デプロイ状況のすべてが同期していることを報告する。
