# 01_UIUX Design Book

## 第1章：デザインシステム (Design System)

### 1.1 デザイン原則 (Design Principles)

* **考えさせない (Don't make me think):** 視線移動を最小限に抑え、次に何をするべきか直感的にわかる配置。
* **ノイズレス (Noiseless):** 業務に関係のない装飾を徹底的に排除。コンテンツとデータが主役。
* **キーボードファースト (Keyboard First):** マウスに持ち替えず、ショートカットキーとTabキーで主要な入力が完結する。
* **明確なコントラスト (Clear Hierarchy):** 最も重要なアクション（保存、確定など）が1画面に1つだけ強調される。

### 1.2 カラーパレット (Color System)

清潔感があり、長時間の業務でも目が疲れにくい低彩度のカラーを採用します。

* **Brand / Primary (主幹色)**
  * `Primary-500`: `#0F172A` (Tailwind `slate-900`) - Linearのような引き締まったダークスレート。主要ボタン、アクティブタブに使用。
  * `Primary-50`: `#F8FAFC` (Tailwind `slate-50`) - 選択中の背景色など。
* **Neutral (ベース/テキスト)**
  * `Background`: `#FFFFFF` - メインコンテンツエリアの背景。
  * `Surface`: `#F9FAFB` (Tailwind `gray-50`) - サイドバー、設定パネルの背景。
  * `Text-Main`: `#111827` (Tailwind `gray-900`) - 見出し・主要テキスト。
  * `Text-Sub`: `#6B7280` (Tailwind `gray-500`) - 補助テキスト、プレースホルダー。
  * `Border`: `#E5E7EB` (Tailwind `gray-200`) - 枠線、区切り線。
* **Semantic (状態色)**
  * `Success`: `#10B981` (Tailwind `emerald-500`) - 完了、回収済み、成功。
  * `Warning`: `#F59E0B` (Tailwind `amber-500`) - 保留、期限間近、注意。
  * `Error`: `#EF4444` (Tailwind `red-500`) - エラー、未回収、期限超過。
  * `Info`: `#3B82F6` (Tailwind `blue-500`) - 案内、AIからの提案。

### 1.3 タイポグラフィ (Typography)

可読性を最優先し、システムフォントを活用して軽量かつネイティブアプリのような表示を実現します。

* **フォントファミリー**
  * 英数字: `Inter`, system-ui
  * 日本語: `Hiragino Sans` (Mac), `BIZ UDPGothic` または `Meiryo` (Windows), `Noto Sans JP`
* **フォントスケール (Tailwind基準)**
  * `Heading 1`: 24px (`text-2xl`), Bold - ページタイトル
  * `Heading 2`: 18px (`text-lg`), SemiBold - セクションタイトル、ダイアログタイトル
  * `Body (Main)`: 14px (`text-sm`), Regular - 一覧表、入力フォームなど（※ERPの基準サイズを14pxとし、1画面の情報量を確保）
  * `Caption`: 12px (`text-xs`), Regular - 補足説明、エラーメッセージ

### 1.4 余白とレイアウト (Spacing & Layout)

8pxの倍数を基準（8pt Grid System）とし、リズミカルで整然としたUIを構築します。

* **Spacing (Tailwind Scale)**
  * `2` (8px): コンポーネント内の要素間（アイコンとテキストなど）
  * `4` (16px): フォームの入力項目間、標準的なパディング
  * `6` (24px): セクション間の余白
  * `8` (32px): ページ大枠のパディング
* **レイアウト構造**
  * **Sidebar (左ナビゲーション)** : 幅 240px（固定）。折りたたみ可能（アイコンのみ表示）。
  * **Header (上部)** : 高さ 56px。検索バーとユーザーアクション、AI呼び出しボタンを配置。
  * **Main Content (中央)** : 最大幅は制限せず、画面幅に合わせて可変（Fluid）。ただし、入力フォームなどは読みやすさのため最大幅（max-w-3xlなど）を設ける。

### 1.5 アイコン (Icons)

* **ライブラリ** : **Lucide React** （シンプルでストロークの太さが均一。LinearやNotionとの親和性が非常に高い）
* **ルール** :
* 基本サイズ: 16px (`w-4 h-4`) または 20px (`w-5 h-5`)
* 線の太さ (Stroke width): 2px または 1.5px で統一。
* 塗りつぶし（Solid）ではなく、アウトライン（Outline）を基本とする。

### 1.6 デザイントークン (実装向け変数定義イメージ)

後段のPhaseでTailwindの設定ファイル (`tailwind.config.ts`) にそのまま落とし込めるよう、設計を変数化しておきます。

* `radius-md`: 6px (少し丸みを持たせつつ、シャープでプロフェッショナルな印象)
* `shadow-sm`: 一覧表やカードの浮き出し効果用（ノイズを減らすため、影は最小限にする）

## 第2章：一覧表（Table）コンポーネント設計

### 2.1 役割と基本思想

ERPにおける一覧表は「情報のハブ」です。複雑なデータを一度に見せる必要がありますが、画面がごちゃごちゃして見にくくなるのを防ぐため、「ノイズレス（余計な線や色をなくす）」 **と** 「キーボードファースト」を徹底します。

* **Excelのようなセル単位の枠線は廃止**し、視線の横移動を助ける「控えめな水平線」のみを使用する。
* マウスに持ち替えず、キーボードの「上下キー」で選択行を移動でき、「Enter」で詳細画面を開けるようにする。

### 2.2 スタイリングルール (Tailwind CSS基準)

* **ヘッダー (Thead)**
  * 背景色: 透明、または極めて薄いグレー (`bg-gray-50`)
  * テキスト: 12px (`text-xs`)、太字 (`font-semibold`)、色は補助テキスト色 (`text-gray-500`)
  * 余白: 上下 `py-3`、左右 `px-4`
* **データ行 (Tbody - Tr)**
  * 背景色: 基本は白 (`bg-white`)。ホバー時（マウスが乗った時）に薄いグレー (`hover:bg-slate-50`) に変化させ、クリックできることを直感的に伝える。
  * テキスト: 14px (`text-sm`)、メインテキスト色 (`text-gray-900`)。
  * 枠線: 下部にのみ1pxの薄い線 (`border-b border-gray-100`) を引く。縦線は引かない。
  * 余白: 情報量を確保するため、上下の余白は詰め気味にする（`py-2` または `py-3`）。
* **行のクリック**
  * 行全体のどこをクリックしても「案件詳細画面」へ遷移するようにする（行全体をクリッカブルにする）。

### 2.3 インタラクションと機能

* **アクションメニュー（右端）**
  * 編集や削除などの操作ボタンは、普段は隠しておき、マウスが行に乗った時（ホバー時）だけ右端にフワッと表示させる（ノイズ低減のため）。
* **ソート（並び替え）**
  * ヘッダーの項目名をクリックすると並び替えられる。並び替え可能な列には、ホバー時にソートアイコン（上下矢印）を表示。
* **列の固定 (Sticky)**
  * 横に長い表になる場合、左端の「案件番号/顧客名」と、右端の「アクション」列は固定され、横スクロールしても常に見える状態にする。

### 2.4 ステータス（状態）の表現方法

案件（Job）の進行状況は、文字だけでなく「色付きの小さなバッジ（Badge）」で視覚的に瞬時に判別できるようにします。第1章で定義したSemantic（状態色）を使用します。

* **未対応 / 保留** : 薄い黄色の背景 + 濃い黄色の文字 (`bg-amber-100 text-amber-800`)
* **進行中 / 手配済** : 薄い青の背景 + 濃い青の文字 (`bg-blue-100 text-blue-800`)
* **完了 / 請求済** : 薄い緑の背景 + 濃い緑の文字 (`bg-emerald-100 text-emerald-800`)
* **エラー / 期限超過** : 薄い赤の背景 + 濃い赤の文字 (`bg-red-100 text-red-800`)

## 第3章：入力フォーム（Forms）コンポーネント設計

### 3.1 役割と基本思想

入力フォームは、オペレーターの入力負荷を極限まで下げることを目的とします。「電話対応をしながら、画面を見ずにキーボードの感触だけで入力が進められる」状態を目指します。

* **キーボードフル操作** : `Tab`キーで次の項目へ、`Shift + Tab`で前の項目へ確実に移動する。
* **ショートカット保存** : フォームの最後でボタンをクリックしなくても、`Ctrl + Enter`（Macは `Cmd + Enter`）でいつでも保存（確定）できるようにする。
* **AIによる入力補助** : 顧客名を入力した段階で、過去の履歴から「回収品目」や「希望時間帯」の予測をAIがサジェスト（提案）し、Enterキーでそのまま入力できるようにする。

### 3.2 スタイリングルール (Tailwind CSS基準)

フォームが「今どこを入力しているか（フォーカス状態）」を一目でわかるようにします。

* **入力フィールド (Input / Textarea)**
  * 背景色: 基本は白 (`bg-white`)
  * 枠線: 通常時は薄いグレー (`border-gray-300`)、角丸 (`rounded-md`)。
  * フォーカス時（入力中）: 主幹色で太い枠線を出し、現在地を強調する（`focus:ring-2 focus:ring-slate-900 focus:border-slate-900`）。
  * テキスト: 14px (`text-sm`)、十分な余白（`px-3 py-2`）を取り、文字が詰まって見えないようにする。
* **ラベル (Label)**
  * 視線移動を「上から下」の一次元にするため、ラベルは入力フィールドの「左」ではなく「上」に配置する。
  * テキスト: 14px (`text-sm`)、太字 (`font-medium`)、色はメインテキスト色 (`text-gray-900`)。
* **必須マーク**
  * 赤い「*」や「必須」という自己主張の強いバッジではなく、ラベルの横に控えめな赤いドット等で表現し、ノイズを減らす。

### 3.3 電話受付に特化したUI要件

* **スマート検索 (Combobox/Autocomplete)**
  * 顧客名や電話番号の入力欄は、数文字打つだけで候補が即座にドロップダウン表示されるようにする。
* **郵便番号・住所の自動入力**
  * 郵便番号を入れた瞬間に住所が自動入力されるのは当然として、熊本県・山鹿市などのよく使うエリアは初期値として設定、または優先表示させる。
* **カレンダー入力**
  * マウスで日付を選ぶカレンダー（Datepicker）も用意するが、「今日」「明日」「明後日」のようなテキストを打てば、自動で日付に変換される機能を持たせる。

### 3.4 エラーハンドリング (バリデーション)

* **インライン表示** : エラーが起きた際、ポップアップ（ダイアログ）で警告を出すのは作業の手を止めるため禁止。入力フィールドのすぐ下に、赤い文字（`text-red-500 text-xs`）で理由（例：「電話番号が短すぎます」）を控えめに表示する。
* **リアルタイムチェック** : 「保存」ボタンを押した時ではなく、入力して別の項目に移った瞬間にエラーを検知して表示する。

## 第4章：ナビゲーションとダイアログ（Navigation & Dialogs）

### 4.1 ナビゲーション（Sidebar & Header）の役割と基本思想

画面の移動は、「今どこにいるか」が直感的にわかり、かつコンテンツの邪魔をしない（ノイズにならない）配置を基本とします。

* **コマンドパレットの導入 (最重要)** :
* 画面のどこにいても、`Ctrl + K`（Macは `Cmd + K`）を押すと画面中央に検索窓（コマンドパレット）が出現。
* 「顧客検索」「新規案件作成」「設定を開く」などのアクションを、キーボード入力だけで即座に実行できるようにする（メニューをマウスで探す手間をゼロにする）。
* **サイドバー (Sidebar)** :
* 画面左側に配置。アイコンと文字で構成し、画面を広く使いたい場合はアイコンのみの細い状態に折りたためるようにする。
* 現在開いているメニューだけが主幹色（`Primary`）でハイライトされ、それ以外は目立たないグレー（`Text-Sub`）とする。
* **ヘッダー (Header)** :
* 画面上部に配置。左端に「現在地（パンくずリスト）」を表示し、迷子を防ぐ。
* 右端にはユーザーアイコンや通知、AIアシスタントを呼び出すボタンを配置。

### 4.2 ナビゲーションのスタイリング (Tailwind CSS基準)

* **Sidebar** :
* 背景色: 薄いグレー (`bg-gray-50`) または白 (`bg-white`)。
* 区切り線: 右側に1pxの薄い線 (`border-r border-gray-200`)。
* アクティブ（選択中）項目: 背景を主幹色に (`bg-slate-900`)、文字とアイコンを白 (`text-white`) にして明確なコントラストをつける。
* **Header** :
* 背景色: 白で少し透過させ、後ろがうっすら透けるモダンな表現 (`bg-white/90 backdrop-blur-sm`)。下部に1pxの線 (`border-b border-gray-200`)。

### 4.3 ダイアログ（Dialog / Modal）の役割と基本思想

ダイアログ（ポップアップ画面）は、画面遷移をせずに「ちょっとした入力（スポット回収の追加など）」や「重要な確認（削除など）」を行うために使用します。多用するとユーザーの作業を遮るため、必要な場面に限定します。

* **キーボードでの離脱・確定** :
* どのような状態でも `Esc` キーを押せば必ずダイアログが閉じるようにする。
* 入力が完了したら `Ctrl + Enter` (Macは `Cmd + Enter`) で保存・確定できるようにする。
* **自動フォーカス** :
* ダイアログが開いた瞬間、自動的に最初の入力項目にカーソルが合い、すぐに文字入力が始められるようにする。

### 4.4 ダイアログのスタイリング (Tailwind CSS基準)

* **バックドロップ (背景のオーバーレイ)** :
* 画面全体を少し暗くし、背景の操作ができないことを示す（`bg-black/20 backdrop-blur-sm`）。真っ黒にはせず、元の画面がうっすら見える程度の「ノイズレス」な表現にする。
* **ダイアログ本体 (Surface)** :
* 背景色: 真っ白 (`bg-white`)。
* 角丸と影: 少し大きめの角丸 (`rounded-xl`) と、浮かび上がって見える影 (`shadow-2xl`) をつける。
* 配置: 画面の中央に配置。サイズは用途に合わせて最大幅を制御する（例：確認用は `max-w-md`、入力用は `max-w-2xl`）。

## 第5章：カードとダッシュボード（Cards & Dashboard）

### 5.1 ダッシュボードの役割と基本思想

ダッシュボードは「今日やるべきこと」と「現在の経営・業務状況」を瞬時に把握するための指令室です。情報過多にならないよう、不要なグラフや装飾は省き、アクションに直結する情報だけを配置します。

* **案件（Job）中心の俯瞰** : 受付待ち、進行中、請求漏れなどのステータスが、Linearの「カンバンボード」のように列で整理されて一目でわかる。
* **AIアシスタントの常駐** : ダッシュボードの特等席（画面右側や上部）にAIパネルを配置。「〇件の請求漏れがあります」「今日のスポット回収ルートを最適化しました」など、AIからのプロアクティブな提案を表示する。

### 5.2 カード（Card）コンポーネントのスタイリング

ダッシュボード上の各要素（KPI、予定、案件など）は、「カード」と呼ばれる白い箱の中に配置します。ノイズレスなデザインを保つため、枠線や影は極力薄くします。

* **基本スタイル (Tailwind CSS基準)** :
* 背景色: 真っ白 (`bg-white`)
* 角丸: 少し大きめで親しみやすい角丸 (`rounded-xl` または `rounded-2xl`)
* 枠線・影: 枠線は引かずごく薄い影をつける（`shadow-sm`）、または、影をなくして極めて薄い枠線を引く（`border border-gray-100`）。どちらかに統一し、画面が重くならないようにする。
* 内側の余白: たっぷりとる（`p-5` または `p-6`）。

### 5.3 KPIパネルの設計

売上、本日の受付件数、スポット回収件数など、重要な数字を示すカードです。

* **数字を主役に** : 数字のフォントサイズを大きくし（`text-3xl font-bold`）、ラベルは小さく（`text-sm text-gray-500`）配置してコントラストを強める。
* **前日/前月比（トレンド）** :
* 数字の横に小さく「↑ +5%」や「↓ -2件」と表示する。
* 良い兆候（売上増など）は緑 (`text-emerald-500`)、悪い兆候（エラー増など）は赤 (`text-red-500`) で色分けし、直感的な把握を助ける。

### 5.4 案件カンバン（Kanban Board）の設計

ダッシュボードのメインとなる、進行中の案件をステータスごとに並べるエリアです。

* **列（カラム）の構成** : 「未対応」「手配済」「回収済/請求待ち」など、業務フローに沿った列を並べる。
* **ドラッグ＆ドロップ** : カードをマウスで掴んで隣の列へ移動させるだけで、直感的にステータスを変更できるようにする。
* **コンパクトな情報量** : カンバン上の案件カードには、「顧客名」「案件概要」「担当者アイコン」「期限（ラベル色付き）」のみを表示し、詳細はクリックして確認する。
