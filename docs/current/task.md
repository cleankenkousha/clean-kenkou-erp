- **改修内容**:
  1. **型定義の追加**: `src/types/index.ts` の `JobStatus` に `'scheduled'`（日程確定）を追加。
  2. **双方向ステータスマッピング**: `src/lib/statusMapping.ts` を改修。
     - `'scheduled'` ⇔ `'日程確定'` の双方向マッピング。
     - 案件メモ内の `stepsData.schedule_confirmed?.status === '済'` によるスマート復元判定。
  3. **モーダルとチェックリストの完全自動同期**: `src/components/features/TaskDetailModal.tsx` を改修。
     - 上部の「現在のステータス」セレクトで「日程確定」を選んだ際、下部チェックリストの「日程確定」も自動で「済」に連動。
     - 逆にチェックリストで「日程確定: 済」を押した際も即座にステータスが「日程確定」に昇格。
     - 保存時にも `schedule_confirmed: 済` を確実に保証して保存。
  4. **案件一覧（Jobs画面）への反映**: `src/pages/Jobs.tsx` を改修。
     - シアン色（青緑）の「日程確定」ステータスバッジを追加。
     - PCテーブル表示・モバイル用カードリスト・CSVエクスポートすべてに「日程確定」を反映。
  5. **DB制約に対する二重安全設計（フォールバック）**:
     - `src/hooks/useJobs.ts` で、Supabase側のCHECK制約が未更新の場合でも自動で `arranged` として安全保存し、メモ（`stepsData`）の「日程確定: 済」から画面復元する保護機構を実装。
  6. **DBマイグレーションスクリプト**: `supabase/add_scheduled_status.sql` を作成。

## 2. 次回以降の残課題・今後の実装計画

### 🚀【新規重要タスク A】各担当スタッフのログイン認証・アカウント管理機能

- **背景・課題**:

  - 現在は `profiles` テーブルに表示名と役割のみが登録されており、実際のシステムログインは共通アカウントや手動管理に依存している。
  - 各スタッフごとの個別アカウント（メールアドレス＋パスワード）を設定・発行し、誰が受付・見積・回収サイン・ステータス更新を行ったかの証跡を確実に担保し、担当者ごとの最適画面（マイタスク）を提供したい。
- **要件定義・実装内容**:
  1. **設定画面からのアカウント発行・管理**:
     - `src/pages/Settings.tsx` の「担当者・作業スタッフ管理」タブを拡張。
     - スタッフ追加時に「メールアドレス」「初期パスワード」を入力可能にし、Supabase Auth にユーザーを登録（または招待）する。
     - 既存スタッフに対するパスワードリセット・再発行リンク送信機能。
  2. **パスワード変更UI（全スタッフ向け）**:
     - ヘッダー右上のユーザーメニュー等から、ログイン中のスタッフ自身がパスワードを変更できるモーダル。
  3. **ロール・役職に応じたアクセス制御（RBAC）**:
     - 管理者（admin）: 全機能・全設定へのアクセス。
     - 事務（clerk）: 案件受付・見積・スケジュール入力・請求発行。
     - 営業（sales）: 案件・見積・自身のスケジュール管理・顧客一覧。
     - 配車（dispatcher）: 配車ボード・ルート作成・案件ステータス調整。
     - 現場（operator）: 担当案件の確認・電子サイン受領・写真撮影・完了報告。
  4. **マイタスク・担当案件の自動絞り込み**:
     - ログインしたスタッフIDに基づき、ダッシュボードやカンバンボードで「自分の担当案件」を1タップでフィルタリング可能にする。

### 🚀【新規重要タスク B】営業担当スケジュール ＆ 事務員見積訪問枠予約カレンダー機能
- **背景・課題**:
  - お客様から見積依頼の電話が入った際、事務員が営業担当の空き時間を電話で確認する往復のタイムロス（連絡のわずらわしさ・顧客の保留/折り返し待ち）が発生している。
  - 営業担当が外出先やスマホから自分の予定をあらかじめ登録でき、事務員がGoogleカレンダーのような見やすい画面で営業の空き枠を確認し、その場で即座に見積訪問アポを登録・確定できる仕組みが求められている。
- **要件定義・実装内容**:
  1. **新規スケジュール/カレンダー画面（`/schedule`）の新設**:
     - ナビゲーションバーに「スケジュール」メニューを追加。
     - **「営業担当タイムライン（日別）」ビュー**: 営業担当者（廣田さん、原口さん等）が横並びになり、縦軸の時間帯（8:00〜18:00）で各担当者の空き状況が一目瞭然になるビュー。
     - **「週間・月間カレンダー」ビュー**: 全体や担当者ごとの予定を俯瞰できる Google カレンダー風のUI。
  2. **予定の種類（視覚的な色分け）**:
     - 🟦 **営業個人の予定**: 外出、打合せ、役所手続き、移動、私用・休暇など（営業本人が直接入力）。
     - 🟧 **見積訪問アポ（案件連動）**: 事務員または営業が入力した顧客見積アポイント。
     - 🟩 **現場回収・立ち会い**: 回収作業の同行や立ち会い予定。
  3. **空き枠クリックからの「即時見積アポ登録」フロー**:
     - 事務員が電話対応中、営業の空いている時間帯をカレンダー上でクリック（またはドラッグ）。
     - 「見積訪問予約」ポップアップが開き、顧客名・電話番号・住所・品目メモを入力して保存。
     - 保存と同時に **新規案件（`jobs`）の作成 ＆ スケジュール枠の確保** が一括で完了。
  4. **営業マン向けスマホ・タブレット最適化**:
     - 外出先からスマートフォンで手軽に「予定の追加・時間変更」ができるシンプルな入力UI。
     - 事務員が入れてくれた新しい見積予定がリアルタイムに画面に反映。
     - 予定詳細から「Google マップでルート案内を開く」「ワンタップでお客様に電話」「そのままAI写真見積・電子サイン画面へ遷移」できる直結ボタン。
  5. **DBテーブル設計（新規予定マスター）**:
     - `staff_schedules` テーブルの作成:

       ```sql
       CREATE TABLE public.staff_schedules (
           id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
           profile_id UUID NOT NULL REFERENCES public.profiles(id) ON DELETE CASCADE,
           job_id UUID REFERENCES public.jobs(id) ON DELETE SET NULL, -- 案件と連動する場合
           title TEXT NOT NULL,
           schedule_type TEXT NOT NULL DEFAULT 'appointment' CHECK (schedule_type IN ('appointment', 'meeting', 'away', 'private', 'other')),
           start_time TIMESTAMPTZ NOT NULL,
           end_time TIMESTAMPTZ NOT NULL,
           is_all_day BOOLEAN NOT NULL DEFAULT false,
           location TEXT,
           notes TEXT,
           created_by UUID REFERENCES public.profiles(id),
           created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
           updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
       );
       ```
