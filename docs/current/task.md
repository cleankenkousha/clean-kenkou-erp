## 1. 本日の作業サマリー（2026-11-04）

### 1-1. スタッフ氏名変更・削除時の自動復活バグ修正＆「桑村りな」様への更新（v1.2.0）【完了】

* **事象**: システム設定で「木下りな」様を「桑村りな」様へ変更・削除しても、画面を再読み込みすると「木下りな」が再び表示されてしまう事象が発生。
* **原因**: `src/hooks/useProfiles.ts` の `fetchProfiles` 処理において、画面を開くたびにハードコードされた初期8名（`DEFAULT_PROFILES`）を `display_name` キーで強制マージし、Supabase DB へ `upsert`（自動再登録）するロジックが動いていたため。
* **対応**:
  1. `src/hooks/useProfiles.ts`: Supabase DB にスタッフデータが存在する場合は DB のデータを唯一の正（Single Source of Truth）としてそのまま採用し、初期リストを勝手に復活・上書きしないよう改修。
  2. `DEFAULT_PROFILES`（ログイン画面のワンタップ選択用リスト含む）の表記も「木下りな」→「**桑村りな**（`kuwamura@kenkou.co.jp`）」へ更新。
  3. Supabase DB（`public.profiles`）に残存していた旧「木下りな」レコードおよび重複していた旧「中原知美」レコードを直接削除。

### 1-2. テスト用共通アカウント（`test@example.com`）の完全廃止と「担当者・スタッフ管理」の管理者専用化（v1.2.1）【完了】

* **事象**: 本人がログインしていないにもかかわらず、ログイン履歴に「中原知美」のログインが記録されていた。
* **原因**: システム初期に作成されたテスト用共通アカウント（`test@example.com` / ID: `b7ca2bda-...`）に「中原知美」という表示名のプロフィールが紐付いていたため、ブラウザに残っていた `test@example.com` のセッションで画面が開かれた際に「中原知美（`test@example.com`）」として履歴が記録されていた。
* **対応**:
  1. **テスト用共通アカウントの完全削除**: `auth.users` から `test@example.com` を完全削除し、全端末からの共通アカウントログインを不可化。
  2. **過去ログの表記修正**: `public.activity_logs` 内で `staff_email = 'test@example.com'` だった履歴の表示名を「テスト共通アカウント（廃止済）」へ更新。
  3. **担当者・スタッフ管理タブの管理者限定表示化**: `src/pages/Settings.tsx` にて、管理者（`admin`：千葉正和様）でログインしている場合のみ「担当者・スタッフ管理（管理者専用）」タブを表示し、一般スタッフの画面ではタブ自体を非表示化（初期表示タブも自動で「自社情報」へ切り替え）。
