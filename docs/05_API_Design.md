# 05_API Design

## 第1章：API設計思想 (API Philosophy)

### 1.1 Supabase SDKの基本利用

* 本システムでは、自前でREST APIサーバーを構築せず、フロントエンド（React）から **Supabase Client SDK (`@supabase/supabase-js`)** を直接呼び出してデータ操作（CRUD）を行うことを基本とする。
* これにより、開発スピードを大幅に向上させるとともに、通信の記述をシンプルに保つ。

### 1.2 セキュリティと Edge Functions の活用

* フロントエンドから直接SDKを叩くため、データアクセスの権限チェックはデータベース側（RLS: Row Level Security）に完全に委ねる。
* **例外処理** : OpenAI APIへのアクセスや、複雑なデータ加工、外部システム（牛若丸など）との連携といった「フロントエンドに秘密鍵（APIキー）を持たせたくない処理」や「重い処理」は、Supabaseの **Edge Functions** を中継APIとして構築し、そこを経由して実行する。

## 第2章：データ操作ルール (Data Operations)

### 2.1 顧客管理 (Customers)

* **検索** : 電話受付時のサジェスト表示のため、`name`（名前）および `phone`（電話番号）での「あいまい検索（`ilike`）」を多用する。
* **作成/更新** : 新規受付時、存在しない顧客の場合は即座に `insert` し、ID（UUID）を返す。

### 2.2 案件管理 (Jobs - 最重要)

* **一覧取得** : ダッシュボードのカンバンボード表示用に、ステータス（`status`）ごとのデータ取得を行う。未完了の案件を優先的に取得する。
* **ステータス更新** : カンバン上で案件がドラッグ＆ドロップされた際、対象案件の `status` と `updated_at` のみを部分更新（`update`）する。
* **担当者アサイン** : 案件に担当者を割り当てる際、`assigned_to` カラムを更新する。

## 第3章：リアルタイム通信 (Realtime Subscriptions)

### 3.1 ダッシュボードの同期

複数人が同時にシステムを操作する業務環境を考慮し、Supabaseの **Realtime機能** を活用する。

* **対象** : `jobs`（案件）テーブルの変更。
* **挙動** : 誰かが案件のステータスを変更したり、新しい電話受付（新規案件）を作成した瞬間、画面を再読み込み（リロード）することなく、**全オペレーターのダッシュボード（カンバンボード）に即座に変更が反映される**ようにする。

## 第4章：AI機能向けAPI (Edge Functions)

電話要約やサジェストなど、AI機能を利用するための専用APIエンドポイント（Edge Functions）を定義する。

### 4.1 `/ai-suggest` (AI入力補助)

* **役割** : 顧客情報や過去の履歴（直近のSpot Collectionsなど）をOpenAIに渡し、「今回の回収品目や希望時間の予測」を生成して返す。
* **通信** : フロントエンド → Edge Function → OpenAI API → (結果) → フロントエンド

### 4.2 `/ai-analyze-unbilled` (請求漏れ検知)

* **役割** : 定期的にデータベースをスキャンし、「回収完了だが請求されていない案件」をリストアップして、ダッシュボードへの警告（アラート）データを生成する。
