# 00_プロジェクト憲章 (Project Charter)

## 1. プロジェクト概要

* **プロジェクト名** : Clean KENKOU ERP
* **プロジェクト目的** : クリーン健康社専用のAI統合ERPを開発する。市販ソフトの代替ではなく、自社の業務全体を「案件（Job）」を中心に一元管理することを目的とする。

## 2. 最重要方針（牛若丸との関係）

**「牛若丸を置き換えない。役割を完全に分離する」**

* **牛若丸が担当する領域** : 定期ルート回収、定期顧客管理、日常の収集業務、ルート運行管理、定期回収実績
* **Clean KENKOU ERPが担当する領域** : 電話受付、顧客管理、案件管理、見積管理、スポット回収管理、請求管理、売上分析、経営ダッシュボード、AI支援（OCR/音声入力/アシスタント）
* ※必要に応じて、ERP側へ牛若丸のデータを取り込む連携を行う。
* ※当システムは「受付から請求までを管理する案件管理ERP」であり、定期ルート配車システムではない。

## 3. システムコンセプトとUI設計思想

* **テーマ** : 「考えなくても操作できる業務システム」
* **目指す姿** : Apple, Linear, Notion, Figma, Material Design 3 の思想を融合した、業務システムらしくない洗練されたシステム。
* **設計目標** :
* 視線移動最小 / 入力最小 / クリック最小
* AIが次の行動を提案
* キーボード中心操作
* 電話受付30秒以内 / 3クリック以内で主要操作完了

## 4. 開発ルール

1. **設計ファースト** : コードを書く前に、必ず設計書（Markdownドキュメント）を作成・合意する。
2. **AI・IDEの活用** : 設計書をもとに、Antigravity IDE（およびAIアシスタント）を利用して実装する。
3. **仕様変更の順序** : 仕様変更が発生した際は、必ず「設計書 → コード」の順に修正し、ドキュメントの形骸化を防ぐ。

## 5. 開発フェーズ

* **Phase1（MVP）** : 電話受付、顧客管理、案件管理、ダッシュボード
* **Phase2** : 見積管理、スポット回収管理、請求管理、OCR、音声入力
* **Phase3** : AI高度化、牛若丸データ連携強化、経営分析、LINE連携（※GPSは必要性再評価、AI自動配車はVer.1対象外）

## 6. 技術スタック

* **IDE / AI** : Antigravity IDE, ChatGPT (将来的にClaude Code)
* **Frontend** : React, TypeScript, Tailwind CSS
* **Backend** : Supabase
