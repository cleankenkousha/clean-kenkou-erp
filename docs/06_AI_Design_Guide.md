# 06_AI Design Guide

## 第1章：AI設計の基本原則 (AI Design Principles)

### 1.1 AIの役割（Copilotアプローチ）

* 本システムにおけるAIは「決定者」ではなく、常に「優秀なアシスタント（副操縦士）」として振る舞う。
* AIが勝手にデータを上書きしたり、顧客に自動返信したりすることはなく、**AIの提案を人間（オペレーター）が確認し、Enterキーやクリックで承認する**フローを必ず挟む。

### 1.2 主なAI機能（Phase1 & 2）

1. **AI受付補助** : 顧客情報と過去履歴から、今回の依頼内容を予測サジェストする。
2. **電話要約・音声入力** : 雑多なメモや音声データを、構造化された美しい案件データに変換する。
3. **請求漏れ検出** : 業務フローの停滞（回収済みなのに請求されていない等）を自動検知して警告する。
4. **AIチャット (検索・集計)** : 「今日の手配漏れはある？」「〇〇さんの先月の回収実績を出して」といった自然言語の質問に答える。
5. **OCR (Phase2)** : 紙の伝票や書類の写真を読み取り、データ化する。
6. *※AI自動配車についてはVer.1（本プロジェクト）の対象外とする。*

## 第2章：機能別プロンプト設計方針 (Prompt Engineering)

AIを安定して業務システムに組み込むため、AIへの指示（プロンプト）は「必ずJSON形式で返す」などの厳格なルールを設けます。

### 2.1 AI受付補助（予測サジェスト）

* **トリガー** : オペレーターが顧客名または電話番号を入力した瞬間。
* **プロンプト方針** : 過去の `jobs` と `spot_collections` のデータをAIに渡し、今回の依頼の「品目」「量」「希望時間帯」の予測確率を計算させる。
* **システムプロンプト例** :

```text
  あなたは優秀な廃棄物回収受付アシスタントです。
  提供される顧客の過去の回収履歴から、今回依頼される可能性が最も高い「品目」「量」「希望時間帯」を推測し、以下のJSON形式でのみ出力してください。
  { "predicted_item": "段ボール", "confidence_score": 85 }
```

### 2.2 電話要約・テキスト整形

* **トリガー** : オペレーターが急いで入力した単語の羅列（例：「あさって 午後 田中さん 粗大ゴミ トラック2台分くらい」）を変換ボタンで押した時。
* **プロンプト方針** : 必須項目（日時、顧客名、内容、量）を抽出し、不足している情報があれば「〇〇が不明です」と返すようにする。

### 2.3 請求漏れ検出とダッシュボード通知

* **トリガー** : バッチ処理（定期実行）、またはダッシュボード表示時。
* **プロンプト方針** : DBから取得した「異常データ（例：ステータスが `collected` になってから7日経過した案件）」を渡し、オペレーターに親しみやすい警告文を生成させる。
* **出力例** : 「3件の案件が回収完了のまま請求されていません。〇〇株式会社の案件が最も古いです。確認しますか？」

## 第3章：AIへの「してはいけない」制限事項 (Guardrails)

AIが予期せぬ動作をしないよう、システムプロンプトには常に以下の制限（ガードレール）を組み込む。

* **ハルシネーション（嘘）の防止** : データベースに存在しない顧客名や単価、架空の回収品目を絶対に捏造しないこと。情報が足りない場合は「不明」として返すこと。
* **事業領域の分離** : 山鹿市の委託事業に関する知識やルールを、クリーン健康社の業務回答に混入させないこと。
* **トーン＆マナー** : 常に丁寧かつ簡潔なトーンを維持し、業務に不要な冗談や過度な挨拶（「こんにちは！」「お手伝いしますよ！」など）は出力せず、データのみを素早く返すこと。
