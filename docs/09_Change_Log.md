# 09_Change Log

## 第1章：運用ルール (Rules of Change Log)

### 1.1 記録の目的

本ドキュメントは、Clean KENKOU ERPプロジェクトにおける仕様追加、変更、バグ修正の歴史を記録する。
単に「何を変えたか」だけでなく、「なぜ変えたのか（ビジネス上の理由・背景）」を必ず明記することで、将来の開発者やAIが文脈を正確に理解できるようにする。

### 1.2 記録フォーマット

変更が発生した際は、本ドキュメントの「第2章：変更履歴」の**一番上**に新しい履歴を追記していくこと。

* **[バージョン] - 日付**
  * **[変更種別]** (追加 / 変更 / 削除 / 修正) 対象機能や設計書
  * **内容** : 変更の具体的な内容。
  * **理由** : なぜその変更を行ったのか（顧客要望、業務フローの変更、バグ修正など）。
